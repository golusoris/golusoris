# Migration guide — v0.18.0

`v0.18.0` moves the object-storage contracts to `core/storage`. The root
`storage` package re-exports them as type aliases, so code that imports only
the root module keeps compiling unchanged.

## Who is affected

Applications that use `storage/gcs`, `storage/azblob` or
`media/img/pipeline` together with a root module older than `v0.18.0`. Those
modules now name `core/storage` types (`Object`, `ListOptions`, `PutOptions`,
`PresignPutOptions`, `PresignedRequest`, `Bucket`). Before `v0.18.0` the root
`storage` package declared its own, distinct types, so mixing versions fails to
compile.

## Upgrade

Upgrade the root module together with the split modules:

```sh
go get github.com/golusoris/golusoris@v0.18.0 \
  github.com/golusoris/golusoris/storage/gcs@latest \
  github.com/golusoris/golusoris/storage/azblob@latest \
  github.com/golusoris/golusoris/media/img@latest
go mod tidy
```

From `v0.18.0` on, `storage.Object` and `core/storage.Object` are the same
type; no source change is needed. Code that wants to avoid the root module's
dependency graph imports `github.com/golusoris/golusoris/core/storage`
directly:

```go
// before
import "github.com/golusoris/golusoris/storage"

var src = pipeline.SourceFromBucket(bucket) // bucket storage.Bucket

// after
import "github.com/golusoris/golusoris/core/storage"

var src = pipeline.SourceFromBucket(bucket) // bucket storage.Bucket from core
```
